# Test Cases — NextBillion.ai Route Optimization API v2

Endpoints under test: `POST https://api.nextbillion.io/optimization/v2` (submit) → `GET https://api.nextbillion.io/optimization/v2/result?key=…&id=…` (poll).
Auth: `key` **query parameter** · Coordinates: `"latitude, longitude"` strings in `locations.location`, referenced by integer `location_index` (WGS84) · Distances in meters · Durations/timestamps in seconds.

**Test Data = the complete, ready-to-send `POST /optimization/v2` request body** (minified JSON) — copy and POST as-is. The poll step is only a URL with the returned `id`.
**Async flow for every case:** submit → assert `status:"Ok"`, capture `id` → poll `/result` until `result.code` present → assert on `result`.
**Negative channels:** malformed/unauthorized/oversized → `4xx` at submit; individually infeasible task → `200` + `result.unassigned`; wholly unsolvable request → `422`.

**API Error Codes:** `200` success · `400` input validation failed · `401` key missing/invalid · `403` no access to resource · `404` host/path not found · `413` request too large · `422` request unsolvable · `429` too many requests · `500` internal error.

**Fields:** Test Case ID · Feature · Title · Description · Test Data · Details · Expected Result · Priority · Type.
**Categories:** Positive · Negative.
